# Domain documentation

This is a single-context repository. Read root [CONTEXT.md](../../CONTEXT.md) before exploring; read [docs/adr](../adr/README.md) records relevant to the work. Use [architecture](../architecture.md) for module boundaries and [development](../development.md) for checks and packaging.

Use the glossary's vocabulary in issues, hypotheses and code discussions. If a concept is missing or ambiguous, flag the gap rather than inventing a competing term. If proposing a change that conflicts with an ADR, name that conflict and seek a decision; do not silently override it. Observed ADRs establish current behavior, not undocumented historical motivations.

If these documents are missing in a checkout, proceed with code inspection; do not invent their contents. No `CONTEXT-MAP.md` or per-module contexts are required for the current layout. The README owns maker-facing contract examples; HANDOFF is historical session context, not deployment authority.
